# Environment and local visibility

The patient frontend is `HEALTHCARE/HealthCare` on Vite port 5173. The API is `HEALTHCARE` on port 4000. The separate `admin-panel` is a different Vite application. Start the API with `cd HEALTHCARE && npm start`, then the patient frontend with `cd HEALTHCARE/HealthCare && npm run dev`. `npm start` compiles TypeScript before launching `dist/server.js` but does not watch files, so restart the API after backend changes. The frontend production build runs strict TypeScript checking before Vite. The local site is `http://localhost:5173`. A hosted website will not reflect uncommitted local changes.

Copy `HEALTHCARE/.env.example` to `HEALTHCARE/.env` and set `DATABASE_URL`, `SUPABASE_URL`, and `SUPABASE_PUBLISHABLE_KEY`. `DATABASE_URL` must point to the intended development PostgreSQL database. Supabase Auth manages login sessions; the backend validates access tokens through Supabase. `PORT` defaults to 4000. Set `CORS_ORIGINS` to the exact frontend origins. Keep `ECG_OPERATOR_KEY` and `CLINICIAN_OPERATOR_KEY` on the backend only. Set `GEMINI_API_KEY` to enable Heartline Companion, the chat available on every page to signed-in accounts; without it the chat reports that Gemini is not configured. `ENABLE_DEMO_CLINICIANS` must be false outside isolated development. ECG simulator variables are optional and must identify a dedicated test device and session. The frontend `VITE_BASEURL` is the API prefix, for example `http://localhost:4000/api/v1`; it is public configuration, never a secret. Restart Vite after changing `.env`.

The patient registration and login pages include **Continue as demo patient**. This opens the normal patient workspace without email provider credentials, PostgreSQL, or a device. Profile edits, health records, appointment booking, ECG recordings, and clinician preview use sample data stored only in the browser tab. The API client handles demo requests locally and sends no demo data to the backend. No account or JWT is created; demo appointments and recordings are simulations. Use **Exit demo** to clear the tab's sample data.

Run migrations only after reviewing the target database and backups: `cd HEALTHCARE && npm run db:migrate`. The command runs migrations 001–009, including Supabase Auth profile support. The production Supabase Auth profile migration has been applied. Set a separate `ECG_REVIEW_SIGNING_KEY` of at least 32 characters before clinicians sign reviews. For optional family alerts, follow [HEALTHCARE/BP_ALERTS.md](HEALTHCARE/BP_ALERTS.md). Rotate credentials with their owning service and keep secrets out of `VITE_` variables.
